# 开发路线

## P0：仓库与规划（本次范围）

- [x] 明确 V0.1 为文件解析与数据展示。
- [x] 建立模块目录、数据约定及界面规划。
- [x] 建立本地样本忽略规则和协作模板。
- GitHub 仓库创建与同步结果以实际远端状态为准。

## P1：真实数据核验（尚未开始）

- [ ] 取得一份用户授权的 LMU 原生 `.duckdb` 文件。
- [ ] 核实实际表结构、单位、时间与圈次语义。
- [ ] 列出支持 / 缺失通道并记录识别规则。
- [ ] 选定解析依赖，确认源文件只读访问策略。

完成标准：能解释样本结构，圈时与关键通道数值可人工核对，不靠猜测建立字段映射。

## P2：最小读取与模型

- [ ] 只读打开文件并提供结构诊断。
- [ ] 建立会话、圈次及通道模型。
- [ ] 正确区分完整性、有效性、缺失数据与零值。
- [ ] 添加针对实际边界的解析测试。

## P3：基础展示

- [ ] 确定界面框架，建立文件导入和圈次选择。
- [ ] 展示核心通道，提供同步游标与缩放。
- [ ] 完成单位、缺失区间及异常状态的显示。
- [ ] 在可信距离可用时提供距离横轴和两圈叠加。

## P4：V0.1 验收与交付

- [ ] 用真实授权样本人工核对图表、圈时与原始数据。
- [ ] 核对首尾残圈、空通道、不同采样频率、损坏及占用文件。
- [ ] 实测长会话的加载时间、内存和图表交互表现，记录测试设备及样本规模。
- [ ] 确认导入前后源文件内容未变。
- [ ] 补齐依赖锁定、Windows 启动 / 打包及使用说明。
- [ ] 完成后再发布 V0.1；规划完成不等同于软件发布。

## 后续候选（未承诺）

赛道图联动、更多遥测通道、导出、实时共享内存接入。自动驾驶分析和 AI 不属于当前路线，新增范围需另行确定。
