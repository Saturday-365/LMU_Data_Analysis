# V0.2 练习信息字段核验

2026-09-17。对本地现有 Monza / GT3 样本进行只读核验；相关结论限于该文件。天气和调教在终端出现的乱码经 Unicode 检查确认属于显示编码问题，不能据此判断原始数据损坏。

| 信息 | 原始来源 | 单位 / 频率 | 时间语义及当前处理 |
| --- | --- | --- | --- |
| 车辆标识、组别 | CarName / CarClass | 文本 | 练习元数据；CarName 为参赛车辆标识，不自动当作标准车型名 |
| 赛道、布局、练习类型 | TrackName / TrackLayout / SessionType | 文本 | 练习元数据；保留原始文本 |
| 录制时间 | RecordingTime | 原始 ISO 风格文本 | 样本含 Z；保留原始时区，不能用导入时间补成录制时间 |
| 气温 | Ambient Temperature | C / 1 Hz | 样本约 15.9944～17；展示所选范围内最小、最大值，保留首末采样值 |
| 赛道温度 | Track Temperature | C / 1 Hz | 样本约 37.3333～39.0059；按圈次范围提取 |
| 风速 | Wind Speed | m/s / 1 Hz | 样本约 4.0026～7.0074；按圈次范围提取 |
| 风向原始角值 | Wind Heading | 源目录声明 deg / 1 Hz | 样本约 3.1204～3.1416；仅显示原值和源单位，不推断东南西北、不擅自按弧度转换；方向约定待核实 |
| 燃油 | Fuel Level | L / 20 Hz | 样本恒定 92；仅展示观测值，不据此推算油耗 |
| 天气说明 | WeatherConditions | 文本“微云” | 无生效时间；整场页显示元数据快照，自动的每圈天气保持未知 |
| 调教 | CarSetup | JSON，样本 172 个顶层项 | 有 stringValue/value 等信息；value 可能是设置索引，不等同物理参数。参数语义及生效时刻未核实，不据此判为默认调教 |
| 干湿 / 抓地 | Minimum Path Wetness / OffpathWetness 等 | 事件 | 有相关字段，不足以表示完整赛道状态；显示未知，允许说明 |
| 轮胎、损伤、辅助 | TyresCompound / WheelsDetached / ABSLevel / TCLevel 等 | 事件，枚举待核实 | 有相关字段时标为未知，缺少时标为未记录，不填“无损伤”或“关闭” |
| 车型、游戏版本、调教名称及备注 | 无已核实自动映射 | 用户填写 | 与遥测值分开保存；不从文件名或车辆表现猜测 |

连续通道沿用 GPS 时钟加声明频率的重建方式，仅接入频率可整除时钟、采样数量一致、行连续且源单位匹配的通道。未知单位、缺表、缺值或时间轴异常分别保留状态；不会把非法值补成零。选圈按 `[start_s, end_s)` 提取，整场包含录制末采样；样本相位尚未独立核实。

## 编辑与优先顺序

- 固定字段只能对整场编辑；天气、燃油、车况与调教说明可对整场或指定完整圈编辑。
- 展示顺序：该圈补录 → 整场补录 → 该圈自动值。整场变化信息的补录是用户明确声明适用于整场。
- “恢复自动 / 继承值”删除当前范围补录；有整场补录时先恢复继承，清除整场补录后恢复遥测值。
- 已知零值、未知、未记录、不适用分开保存。每项保留单位、来源字段、适用范围、原值和补录修改时间；自动值的修改时间为 null，表示源文件读取值。
- 调教参数本版通过带单位的说明手录，没有四轮参数结构化解释或独立调教文件导入。

## 接口

`GET /api/v1/sessions/{id}/conditions` 返回整场信息；添加 `?lap_id={id}` 返回指定圈次及继承状态。字段包含定义、`automatic`、`effective`、`own_override`、`inherited_override`。自动范围值结构为 `{min,max,first,last}`；手工数值为标量，状态通过 `state` 区分。

`PATCH` 使用同一路径与可选圈次参数，需要现有 `X-LMU-Client: web` 及同源访问约束。请求示例：

```json
{"changes":{"fuel":{"state":"known","value":0},"setup_kind":{"state":"unknown","value":null}}}
```

使用 `{"changes":{"fuel":null}}` 恢复当前范围的燃油值。固定字段禁止圈次覆盖，输入一次验证后事务保存。原始 DuckDB 和导入摘要不变，SQLite 附加信息独立存储，重复导入保留全部补录。
