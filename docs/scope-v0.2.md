# V0.2 任务：赛道参照与练习信息

状态：2026-09-17 用户提出，已纳入下一阶段，尚未实现。继续使用本地网页，保留以后服务器部署及云端保存练习、圈次和附加信息的接口边界。

## 任务 1：走线对比加入赛道原始数据

目标：在已有双圈走线上显示可信的赛道参照，方便车手判断车辆与赛道边界、路肩和弯道的相对位置。

- 先调查用户提供或允许使用的赛道数据，记录来源、授权、赛道名称、布局和版本；优先验证一个赛道。
- 核实数据实际包含中心线、左右边界、路肩、维修区或其他几何信息中的哪些内容，只展示有依据的部分。
- 核对遥测局部坐标和赛道数据的坐标系、单位、方向、比例、原点与高程；验证配准误差，不直接把游戏经纬度套到真实地图。
- 支持参照图层开关，并保留原有两圈配色、缩放、平移和游标联动。
- 缺少数据、布局不符或配准不可靠时，提示原因并继续提供原有走线对比；不以车辆轨迹估计结果冒充原始赛道边界。

验收：在已匹配的真实样本上人工核对多个分布在全赛道的参照位置，记录误差及可用范围；误差阈值在确认数据精度后制定。若无法取得可信数据，交付调查结论和可接入的数据约定，不将试验视为已完成的准确底图。

## 任务 2：补充练习记录及影响圈速的条件

目标：让车手查看练习背景和影响圈速的条件；能可靠读取的自动读取，文件未提供的允许用户选择或填写。

| 信息 | 待核验和展示内容 |
| --- | --- |
| 车辆 | 车型、组别、车队 / 车辆标识，以及有来源的游戏版本 |
| 练习 | 赛道、布局、练习类型、记录时间与备注 |
| 天气 | 气温、赛道温度、降雨、风向 / 风速等实际存在的字段 |
| 赛道状况 | 干湿程度、积水、橡胶 / 抓地状态；不可将未知值视为干地或最佳抓地 |
| 车辆运行状态 | 燃油、轮胎配方 / 胎龄 / 状态、损伤、辅助设置等可验证的影响因素 |
| 调教 | 是否使用默认 / 自定义 / 未知调教、调教名称、来源与实际可取得的参数及单位 |

调教参数先清点再决定支持范围，例如胎压、空气动力学、悬架、车高、差速器、制动力分配和齿比。遥测未记录完整调教时，不从车辆行为反推参数；不能证明为默认调教时保持“未知”。用户可补录已知参数，调教文件导入是否可用需另行核验格式。

数据规则：

- 保存遥测原值和来源；用户修订 / 补录单独保存，支持恢复自动值，不改写原始遥测。
- 区分未知、不适用、未记录和真实零值；选择项支持未知和自定义备注。
- 会话固定信息归属练习；天气、燃油、调教变更等时变信息按有证据的时间 / 圈次保存，不把单个时刻的值套用到所有圈。
- 展示来源（遥测读取 / 用户填写）、单位、有效范围及修改时间；来源冲突时保留原值并说明所展示的版本。
- 沿用练习与圈次编号，附加信息可持久化并预留存储迁移；历史记录无新字段仍可正常打开。

验收：至少覆盖自动读取、缺失字段手工补录、用户覆盖与恢复、重启后保留、旧记录兼容，以及时变信息的圈次归属。不同车辆的不可用字段明确提示。

## 推进顺序

1. 清点当前样本的相关字段，建立字段、单位、来源、时间语义及缺失情况清单；同时调查赛道数据来源。
2. 明确数据模型与存储迁移，先交付练习信息的读取、编辑和保存。
3. 对单一赛道做坐标配准试验，通过核验后接入走线界面。
4. 使用更多练习样本验证字段差异、信息归属与兼容性，记录 V0.2 验收结果。

本阶段聚焦数据展示和用户复盘，不加入 AI、自动驾驶建议或自动圈速原因归因。“影响圈速的外部条件”按天气、赛道、车辆状态等理解；视频 / 第三方影像接入暂未纳入已确定任务。
