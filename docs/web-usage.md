# 本地网页端

## 启动

取得仓库源码后，在项目根目录使用 Python 3.12 创建环境。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
```

双击根目录 `start-web.cmd`，保留启动窗口，打开 **http://127.0.0.1:8765**。关闭窗口或按 Ctrl+C 停止服务。Windows EXE 的启动和构建见 [桌面版 V0.6](desktop-v0.6.md)。

也可运行 `.\.venv\Scripts\python.exe scripts/serve_web.py`。端口被占用时附加 `--port 8766`，访问对应地址。可通过 `--data-dir` 更换存储目录，默认是项目内 `data/`。

## 操作

1. 点击选择或拖入一份或多份 LMU 原生 `.duckdb` 文件，每份最大 256 MiB，录制时长至少 60 秒且包含至少 1 个完整圈。结果会分别列出已导入、重复拒绝、已过滤和失败的文件。
2. 在首页「最近录制」选择一条记录，查看左侧预览。点击「打开会话」进入分析，也可从侧栏直接打开会话。
3. 在「驾驶曲线」选择完整圈。可对照同一会话的其他圈，或选取相同赛道布局的其他会话。橙色实线为当前圈，青色虚线为参考圈。
4. 切换距离 / 圈内时间。只有所选圈距离可靠且单调时允许距离轴，否则回退时间。
5. 移动鼠标查看同一位置的驾驶通道。滚轮缩放，拖动平移，双击或点击「全圈」可恢复视图。聚焦曲线区域后可用左右方向键移动游标。
6. “走线对比”使用当前圈和参考圈的原始经纬度，橙色 / 青色对应驾驶曲线。悬停走线可定位曲线游标；悬停曲线可查看两圈地图标记。距离轴按同一圈内距离匹配，时间轴按同一圈内时间匹配。
7. 在走线图上滚轮缩放、拖动平移，或使用加减按钮与“全圈”。勾选“跟随游标看弯道”后，地图跟随曲线游标放大到局部；手动拖动或缩放地图会退出跟随。地图聚焦后方向键平移，加减键缩放，0 恢复全圈。宽屏并排展示地图与曲线，窄屏上下排列。
8. 展开读取状态查看诊断。转向单位为百分比，缺失值为空，挡位以阶梯显示。

在「设置」保存遥测目录后，每次启动本地网页服务会扫描该目录中的 `.duckdb`。也可点击「立即扫描」。浏览器中填写本机服务运行电脑上的完整路径。刷新网页可以查看扫描状态，重新启动服务会重新检查目录。

走线仅是局部坐标投影；圈首方块标记的是第一条圈内 GPS 采样，不是精确终点线。经纬度缺失或明显跳变处不连线，不强制闭合首尾。当前样本为 10 Hz、纬度量化步长约相当于 0.42 m，放大后不能把细小折线解释成真实的微小驾驶差异。没有可靠 GPS 的文件仍可正常查看其余曲线。

游标展示最近的对齐采样值及采样 / 插值 / 保持标记。两圈按各自距离绘制，不生成自动驾驶结论。源采样相位与官方圈有效性仍未核实，“最短记录圈”不表示官方有效最快圈。

## 会话分析

页面顶部可切换五个视图。

- **驾驶曲线**：现有单圈 / 双圈五类通道。
- **圈速总览**：全部圈次、S1 / S2 / S3、距最快圈差值、平均 / 最快 / 理论最快 / 标准差，以及最优分段的来源圈次。残圈单列，缺失值留空。
- **节奏与调教**：逐圈节奏、整场与各驾驶段的圈速分布、进出站记录，以及同场驾驶段或相近录制的 A/B 对照。
- **数据目录**：检查文件里的全部连续通道与事件，支持搜索及候选 / 常量 / 待核实筛选。此页是原始数据清点，不表示所有通道图表均已实现。
- **练习信息**：选择整场或指定圈次，再选择字段、状态并保存；原始自动值始终保留。“恢复自动 / 继承值”移除当前范围的补录，有整场补录时先恢复继承。天气元数据仅为时间未知的快照，不能代表每圈。

走线图在存在合格资源时提供赛道图层开关。字段、补录和赛道参照详见 [练习信息约定](practice-fields-v0.2.md)和 [赛道参照调查与接入](track-reference-v0.2.md)。

统计口径和 Monza 样本结论见 [扩展数据与分段核验](telemetry-opportunities.md)。

## 保存、迁移和升级

在「个人赛道档案」点击「导出全部圈速 CSV」可用 Excel 查看完整圈。保存曲线、圈次、补录和设置时，请备份整个档案目录。

- `data/catalog.sqlite3` 保存本地车手、练习、圈次和稳定编号。
- `data/recordings/<UUID>.duckdb` 保存原始文件副本，源文件不变。
- `data/auto-import.json` 保存自动导入目录和已处理文件记录。
- 文件内容相同会被拒绝导入，改名也会识别为重复。已有会话可在档案列表中打开。
- `data/` 整体被 Git 忽略。备份前停止服务，再复制整个目录；只备份目录数据库不足以恢复曲线。
- 原始副本仍含游戏写入的所有字段；展示接口仅返回元数据白名单，不返回源车手名、Steam ID 或车辆调校。

升级网页版时，停止服务后更新源码，重新安装 `requirements-web.txt` 中的依赖，再启动服务。迁移时关闭两台电脑上的软件，将源档案目录复制到目标电脑，随后可用 `--data-dir` 打开副本。桌面 EXE 默认使用 `%LOCALAPPDATA%\LMU Data Analysis`，详情见 [桌面迁移说明](desktop-v0.6.md#迁移到另一台电脑)。

此版本只监听本机 `127.0.0.1`，没有账号登录、联网同步或云备份。云端替换边界见 [架构说明](architecture.md)。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:LMU_SAMPLE_PATH = '真实样本绝对路径.duckdb'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

未设置样本路径则跳过真实样本检查。修改前端文件后刷新浏览器，修改 Python 服务端后重启。
