# Track Titan 调研与 LMU 功能建议

日期：2026-09-17。状态：分析提案，未实施，不替代已确认的 V0.2 范围。

## 1. 结论与调研边界

建议借鉴 Track Titan 的复盘流程：练习档案 → 选择参考圈 → 定位亏时区间 → 对照驾驶动作 → 建立训练任务 → 追踪进步。继续以 LMU 游戏原生 `.duckdb` 为数据源，优先做可靠的赛后分析和个人训练记录。

本次查看官网、官方功能介绍、公开应用页面、训练计划样例，并核对本仓库读取、存储、计时和前端实现。未登录付费账户、未安装其 Logger、未实际操作带个人数据的会话；公开页可确认功能存在，但不能证明每个游戏支持相同细节。训练日历、个人笔记、标签等下文列为我们的设计建议，不宣称 Track Titan 已提供。

Track Titan FAQ 明确提到独立 Logger，并支持 LMU；未找到足够公开证据确认其 LMU 当前使用共享内存、插件还是其他具体接口，也不能据此断言它完全不使用官方接口。[官方 FAQ](https://www.tracktitan.io/faqs)

LMU 官方确认 PC V1.2 起支持游戏原生 DuckDB 遥测录制，通道和频率可配置。我们的数据路线成立，但每份文件可用字段会受录制配置影响。[官方录制说明](https://guide.lemansultimate.com/hc/en-gb/articles/14524956311695-Telemetry-Recording)

## 3. 当前项目基础

已核对 `web/app.js`、`web/insights.js`、`web/charts.js`、`storage.py`、`web_service.py`、`timing.py`，以及样本核验文档。

- 已有：原生文件导入、按哈希去重、本机持久保存、练习列表、同练习双圈选择、五类驾驶曲线、双圈 GPS 走线和联动游标。
- 已有：圈时、三个分段、最快/平均/中位圈时、标准差、三段理论最快及来源圈次、原始通道目录。
- 缺少：跨练习参考选择、沿距离连续时间差、逐弯区间、驾驶事件标记、历史趋势、可编辑训练档案及任务关联。
- V0.2 已计划但未完成：天气/车况/调教信息及可信赛道参照。本提案与其衔接，不把计划当作已实现。

重要区别：现有“本圈比最快圈慢多少”是整圈差值，不是沿赛道变化的连续时间差；现有理论最快是三个分段的计时组合，不是可直接播放的真实整圈。

## 4. 建议功能清单

P0 为首批闭环必需；P1 为随后增强；P2 为另行研究。优先级是建议，不表示已获实施确认。

| 编号 | 功能 | 具体使用方式 | 数据与限制 | 优先级 |
| --- | --- | --- | --- | --- |
| A1 | 跨练习双圈对比 | 今天某圈对比昨天/历史最佳/收藏圈 | 同布局及距离定义；车辆与条件差异提示；跨文件 GPS 统一坐标 | P0 |
| A2 | 连续时间差与区间亏时 | 曲线显示在哪开始变慢；地图按区间得失着色 | 圈内时间与 Lap Dist；不可用速度差冒充时间损失 | P0 |
| A3 | 逐弯/组合弯导航 | 点击弯道后同步缩放地图和曲线 | 先人工核验单赛道区间；支持连续组合弯 | P0 |
| A4 | 驾驶动作对照卡 | 刹车起点、松刹过程、最低速度及位置、恢复油门/全油门位置、出口速度 | 输入阈值与持续时间可追溯；最低速度点不自动叫几何弯心 | P0 |
| A5 | 参考圈管理 | 收藏、命名、备注，按车/赛道选择个人参考圈 | 自己的原生包；他人提供包需明确来源；不能靠圈速重建遥测 | P0 |
| A6 | 亏时区间排序 | 将最值得查看的几个弯/直道列到前面 | 只排序观测时间差，不自动判定根因 | P1 |
| A7 | 二维联动回放 | 播放/暂停/拖动，两圈轨迹同步查看 | 明确按同时间还是同距离同步；GPS 精度限制 | P1 |
| A8 | 多圈稳定性对照 | 同一弯多圈刹车点/出口速度/区间耗时的分布 | 展示样本数与筛选条件，避免只看最快圈 | P1 |
| A9 | 扩展工程通道 | 转速、G 值、轮胎、刹车温度、ABS/TC 等分组查看 | 先解决四分量轮位、枚举含义和时间对齐 | P1 |
| A10 | 三维/视频回放、自动教练 | 可视化驾驶过程，辅助解释 | 额外资产/同步/模型验证，不是仅有 DuckDB 就完成 | P2 |
| T1 | 可筛选的训练档案 | 按真实训练日期、赛道、车、类型、标签检索 | 录制日期与导入日期分开；时区未知明确标记 | P0 |
| T2 | 练习背景与备注 | 天气、温度、燃油、轮胎、调教版本、训练目的 | 自动值与用户补录分开；变化值按圈/时段归属 | P0 |
| T3 | 训练总结 | 圈数、录制驾驶时长、最快/中位圈、稳定性、最佳分段 | 排除残圈/维修区等；完整性、有效性分别显示 | P0 |
| T4 | 个人进步趋势 | 同车同布局的历史最好、中位圈、稳定性和练习量 | 条件分组；不把天气/燃油变化直接解释为技术进步 | P0 |
| T5 | 训练目标与复盘笔记 | 目标关联某弯、基准圈及后续练习；填写心得/完成状态 | 用户定目标；数据指标辅助，未知有效性不自动判为达标 | P0 |
| T6 | 连续驾驶段分析 | 查看一次出站后的圈速变化与稳定性 | 维修区事件及断点，边界不明时支持手工划分 | P1 |
| T7 | 训练日历/周报 | 练习频率、时间、圈数及完成目标 | 仅统计已导入录制覆盖范围，不称游戏总游玩时长 | P1 |
| T8 | 设置 A/B 记录 | 两种调教关联练习、比较分布与用户反馈 | 设置名称/附件可先手录；完整调教解析待格式核验 | P1 |

目录监测可作为 P1 导入便利功能：发现官方新文件后，等待文件完成且可只读打开再导入；需要去重、重试、失败提示。它仍是赛后文件流程，不承诺实时教练。

## 5. 分析指标的计算边界

### 时间差和区间

在同一条赛道距离坐标上建立两圈的 `t(s)`，定义 `Δt(s) = 当前圈 t(s) − 参考圈 t(s)`，正值表示当前圈落后；区间亏时为终点差减起点差。累计落后与本区间新增亏时分别展示。

- 起终点、距离回绕、倒车、停车、多次经过同位置、缺失区间需要显式处理；不能排序距离数组掩盖非单调数据。
- 两圈只在共同覆盖且可靠的区间比较，不外推缺失数据。
- 原始 Lap Time 仍是整圈计时权威值；连续重建时间差要校验终点与原始圈时差的残差，超阈值标注/停用，不强行拉伸到一致。
- 赛道距离与地图弧长不能混用；跨文件轨迹必须用共同坐标基准。
- 连续弯的影响会延续到直道，允许检查组合区间；“某区间慢”不等于“该区间发生了唯一错误”。

### 驾驶事件

刹车起点、油门恢复、全油门位置均需阈值、迟滞/持续时间和算法版本。支持多次踩踏，保留原始曲线用于核对。转向通道为百分比时不显示为角度；刹车踏板百分比不显示为液压压力。

卡片用“比参考圈提前/延后”“观测值差异”，不直接写“应该更晚刹车”。没有验证过的因果模型，不计算所谓“这一个动作必然损失多少秒”。

### 训练统计

至少区分完整圈、官方有效/无效/未知、是否纳入当前统计、用户标记。未知有效性不得显示成有效率 100%。筛选规则和样本数随图展示；零次记录、缺失字段与真实零值分开。

进步图至少同时呈现最好圈和中位圈/离散程度。同车同布局仍可能受燃油、轮胎、环境、辅助设置和游戏更新影响，保留条件标签，不做未经验证的统一校正。

理论最快继续保留各段来源；未来细分到弯道也只是组合下界，可能无法在一圈内同时实现。

## 6. 官方数据能支撑什么

依据仓库现有真实样本核验记录，以下仅针对已核验 Monza/GT3 样本；本轮未重新录制或重跑全量样本检查。

| 数据 | 现有证据 | 对功能的影响 |
| --- | --- | --- |
| 速度、油门、刹车、转向、挡位、圈时 | 已接入并核对；不同通道频率不一 | 能支持基础双圈和事件提取，但仍需处理采样时间语义 |
| Lap Dist、GPS | 10 Hz，已有局部走线 | 可做区间分析；不能承诺厘米级走线精度或直接叠真实地图 |
| 车型/布局/练习类型/录制时间 | 元数据有相关标识 | CarName 不一定是标准车型名；RecordingTime 时区需核验 |
| 环境温度、风 | 样本存在低频通道 | 可做背景记录；完整干湿/抓地仍待字段核验 |
| 胎温胎压/轮速/悬挂/制动 | 有通道，四分量顺序未确认 | 先完成轮位映射再做四轮可视化 |
| Fuel Level、Virtual Energy | 样本恒定 | 不足以验证油耗/能耗预测，需变化样本 |
| 油温/水温 | 7 Hz 时间重建有已知偏差 | 未解决前不加入精细联动对照 |
| 有效圈判定、完整调教、可信赛道边界 | 未确认或未取得 | 不能从字段名称/车辆行为/轨迹自行补造 |

因此无需为了复刻分析与记录更换数据源；实时覆盖层、视频、专业参考圈库等则需要独立输入或服务。

## 7. 建议页面与记录结构

建议页面：

1. **训练首页**：最近训练、个人最好、同条件趋势、进行中的目标。
2. **训练记录**：筛选列表；打开后看圈次、驾驶段、条件与备注。
3. **分析工作台**：顶部当前/参考圈，中部地图与时间差，下部驾驶曲线；侧边逐弯差异及“加入训练目标”。
4. **训练计划**：目标、基准、关联圈段、练习记录、结果和复盘。
5. **参考圈库**：个人收藏与合法取得的外部原生包，统一标明条件与来源。

在已有练习和圈次编号之上增加：练习补充信息、圈/区间标记、赛道区间版本、参考圈收藏、训练目标、目标与练习/圈段的关联。原始文件保持只读；补录不覆盖遥测原值。衍生指标记录算法版本，数据和规则变化时可重算。多文件属于同一次训练时支持手工归组，不凭相近导入时间自动合并。

## 8. 实施顺序与验收建议

**第一步：接续 V0.2，建立可比较的训练档案。** 补录制时间语义、车辆/布局标识、条件/备注、列表筛选和参考圈收藏。赛道原始数据调查继续并行推进，但不阻塞档案。验收包含补录/恢复、来源可见、重启保留、旧记录兼容、重复文件不重复计数。

**第二步：完成核心分析闭环。** 跨练习双圈 → 连续时间差 → Monza 人工核验区间 → 驾驶事件卡。验收包含两份同布局记录、不同布局拒绝/明确限制、同圈自比接近零、终点残差核验、缺失和回绕处理、图表/地图/区间选择联动。

**第三步：完成训练闭环。** 同车同布局趋势 → 手工训练目标 → 关联基准与后续圈段 → 复盘状态。验收包含日期与导入时间区分、条件过滤、完整/有效未知分离、目标关联持久保存；用前后多次真实训练验证结果。

**第四步：增强分析。** 二维回放、多圈分布、连续驾驶段、工程通道、周报、调教 A/B。先验证真实样本差异，再确定每项支持范围。

本轮不建议进入首批的内容：AI 根因教练、实时语音/覆盖层、3D/视频同步、全网评分/排行榜、专业圈库运营、调教商城。它们不妨碍先实现完整的个人复盘与训练记录。

首批完成的直观标准：导入今天的官方包 → 找到昨天同车同布局的收藏圈 → 看到在哪个弯开始亏时及输入差异 → 保存训练目标 → 下次导入后查看同条件区间指标和稳定性变化。
